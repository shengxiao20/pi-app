3. 不能混淆的边界

        

          

            
技能展开 ≠ 独立旁路运行

            

              /skill:name 先变成
              <skill>…</skill> user
              text，再运行模型。展开文件读取不是工具调用。
            

            

              模型在普通运行中选择读取技能文件，是另一种情况：那次读取会显示为普通工具执行。
            

          

          

            
HTTP 接受 ≠ 扩展成功

            

              HTTP 200 仅说明 SSE 已开始。命令异常可能被 SDK 捕获，但
              onError 仍让适配器最终输出 RUN_ERROR。
            

            

              单独的 error
              级通知不是运行失败；缓存的旧扩展错误也不让新命令失败。
            

          

        

        

          未知技能和技能文件读取失败
          

            当前 SDK 对未知 /skill:name 保留原文。裸
            /skill 没有内置展开。技能文件读取失败会报告
            skill_expansion，但返回原文，模型仍可能运行；适配器最后报告扩展错误。Pi App
            没有新增预检拒绝或自动重试。
          

        

        

          UI、错误横幅与通知历史
          

            ctx.ui.notify 可用。对话框、编辑器、widget、theme
            等方法明确不支持。terminal widget 必须检查
            ctx.mode === "tui"，不能只检查 ctx.hasUI。
          

          

            通知不写入 Pi
            历史，刷新网页后不恢复。旧错误横幅在下一次有效提交时清除；输入、空提交、粘贴图片都不清除。
          

        

        

          取消、断线和运行成功的含义
          

            HTTP abort 请求本身返回 204。适配器从
            agent_settled.aborted 记录取消，并在 prompt 完成后输出
            cancelled。断开浏览器不自动取消模型运行，也没有 SSE 重放接口。
          

          

            工具结果带 error 不一定使运行失败。适配器不映射 SDK 的完整
            outcome，只检查捕获的异常、活动扩展错误、工具结果完整性和 aborted。
          

        

        

          图片上传和历史权威
          

            图片走独立二进制 HTTP 上传：PNG/JPEG/GIF/WebP，最多 20
            MiB，文件头校验，随机临时文件，0600
            权限。只把绝对路径插入草稿，没有附件预览或自动模型图片消息。
          

          

            运行前获取完整 canonical AG-UI 投影，深比较历史并追加一个新 user
            消息。canonical 仅投影文字和工具消息，不等于 Pi 完整模型上下文。
