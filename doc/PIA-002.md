# PIA-002：Tauri 2 + React + TypeScript 工程讲解

本文记录 PIA-002 创建的工程骨架，并解释每层代码的职责、构建过程与运行关系。

## 1. 全局架构

Tauri 是原生桌面应用框架，但它通常在操作系统原生窗口中嵌入系统 WebView 来渲染富 UI。因此本项目有两套协作代码：Rust 负责原生能力，React 负责界面。

```text
┌───────────────────────────────────────────────────────┐
│ Tauri 原生应用（Rust）                                  │
│                                                       │
│ 窗口、打包、文件系统、原生权限、Pi 子进程管理           │
│                        │                              │
│                        ▼                              │
│ 系统 WebView                                           │
│ ┌───────────────────────────────────────────────────┐ │
│ │ React + TypeScript                                 │ │
│ │ 聊天、Markdown、代码块、工具调用卡片、流式状态等   │ │
│ └───────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────┘
```

> React 不是另一个浏览器产品；发布后它的静态资源会被打进 Tauri 应用，由桌面窗口的 WebView 加载。

## 3. 根 npm package

### `package.json`

根 package 同时承担两件事：它是 Pi extension package，且是 `desktop` workspace 的统一入口。

```json
{
  "workspaces": ["desktop"],
  "pi": { "extensions": ["./extensions"] }
}
```

`workspaces` 让根目录能统一执行前端命令，而不必手动进入 `desktop/`：

```text
npm run lint            → desktop ESLint
npm run typecheck       → desktop TypeScript
npm run test:frontend   → desktop Vitest
npm run rust:clippy     → desktop/src-tauri Cargo clippy
```

根目录的质量命令如下：

| 命令 | 用途 |
|---|---|
| `npm test` | 测试 Pi `/app` extension 注册 |
| `npm run format:check` | 校验前端 Prettier 格式 |
| `npm run lint` | 校验 React/TypeScript 静态规则 |
| `npm run typecheck` | 执行 TypeScript 严格类型检查 |
| `npm run test:frontend` | 执行 React/Vitest 单元测试 |
| `npm run rust:fmt` | 校验 Rust 格式 |
| `npm run rust:clippy` | 执行 Rust lint，warning 视为错误 |
| `npm run rust:test` | 执行 Rust 单元测试 |

### `package-lock.json`

`package-lock.json` 由 npm 自动生成，锁定 Node 依赖的精确版本和完整性校验。CI 使用 `npm ci` 时，会安装与本地一致的依赖树。它不应被手动修改。

### `extensions/app.ts`

此文件来自 PIA-001，注册 Pi 交互会话中的 `/app` 命令：

```text
Pi session 中执行 /app
  → extensions/app.ts 的 handler
  → PIA-003 将实现的 launcher
  → 对应平台的桌面二进制
```

当前 handler 明确抛出 “launcher is not implemented yet”。这不是静默失败：PIA-003 会实现平台检测、二进制解析和子进程启动。

### `tests/extension/entrypoint.test.mjs`

测试验证稳定的产品契约：

```text
/app 命令存在
命令名称和描述正确
命令来源是 extension
命令的源文件路径正确
```

加入 workspace 后，Pi 可能把 extension 识别为 package 而非临时 CLI extension。因此测试不再断言 Pi 内部的 `scope`、`origin` 等加载元数据。测试应验证我们承诺的行为，而非第三方未承诺稳定的内部实现。

## 4. React 前端 workspace：`desktop/`

### `desktop/package.json`

此 package 是前端 workspace。

运行时依赖：

| 包 | 职责 |
|---|---|
| `react` | 声明 UI 组件与状态 |
| `react-dom` | 将组件渲染到 WebView DOM |
| `@tauri-apps/api` | 后续调用 Rust command、订阅 Rust event |

后续从 React 调 Rust 的形式会是：

```ts
import { invoke } from "@tauri-apps/api/core";

await invoke("start_agent", { cwd });
```

开发依赖包含 Vite（构建/开发服务器）、Vitest（测试）、TypeScript（类型）、ESLint（静态检查）和 Prettier（格式化）。

### `desktop/index.html`

WebView 首先加载的 HTML：

```html
<div id="root"></div>
<script type="module" src="/src/main.tsx"></script>
```

调用关系：

```text
Tauri WebView
└── index.html
    └── #root
        └── src/main.tsx
            └── React <App />
```

### `desktop/src/main.tsx`

React 挂载入口：

```tsx
createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

- `createRoot`：创建 React 19 渲染根。
- `#root`：对应 `index.html` 内的 DOM 节点。
- `StrictMode`：开发期帮助检测副作用和不安全生命周期用法。
- `!`：TypeScript 非空断言；若 HTML 错误地缺失 `#root`，应直接暴露错误，不能静默继续。

### `desktop/src/App.tsx`

目前是最小可渲染 UI：

```tsx
export default function App() {
  return (
    <main>
      <h1>Pi App</h1>
      <p>Desktop client scaffold</p>
    </main>
  );
}
```

它证明了 TSX 编译、React 渲染、Vite 打包、Vitest 测试和 Tauri 静态资源配置这一整条基础链路。它尚未实现聊天功能；聊天 UI 是 PIA-006 的范围。

未来的组件树预计为：

```text
App
├── ApplicationShell
│   ├── SessionSidebar
│   └── MainPanel
│       ├── ConversationHeader
│       ├── ChatTimeline
│       │   ├── UserMessage
│       │   ├── AssistantMessage
│       │   └── ToolCallCard
│       ├── AgentStatus
│       └── Composer
└── ErrorBoundary
```

### `desktop/src/App.test.tsx`

这是按 TDD 首先写下的测试：

```tsx
render(<App />);
expect(screen.getByRole("heading", { name: "Pi App" })).toBeTruthy();
expect(screen.getByText("Desktop client scaffold")).toBeTruthy();
```

测试顺序：

```text
先写期望 UI → 测试失败（App 不存在）
→ 创建最小 App → 测试继续暴露缺失的 TSX/DOM 配置
→ 配置完成 → 测试通过
```

这是 TDD 的小循环：

```text
Red（失败） → Green（最小实现通过） → Refactor（在测试保护下整理）
```

### `desktop/src/styles.css`

仅提供暗色背景与居中 scaffold：

```text
全窗口高度
└── 居中显示当前 App 内容
```

现在不引入 UI 框架或复杂设计系统，避免在实际 UI 需求到来前过度设计。

### `desktop/tsconfig.json`

关键 TypeScript 选项：

| 配置 | 作用 |
|---|---|
| `strict: true` | 尽早发现 `null`、隐式 `any`、类型不安全问题 |
| `noEmit: true` | TypeScript 只做类型检查，Vite 承担打包 |
| `jsx: "react-jsx"` | 使用现代 JSX transform，无需每个 TSX 文件导入 React |
| `moduleResolution: "Bundler"` | 使用 Vite 风格的现代模块解析 |

### `desktop/vite.config.ts`

```ts
export default defineConfig({
  plugins: [react()],
  test: { environment: "jsdom" },
});
```

- React 插件处理 TSX 与 React fast refresh。
- `jsdom` 在 Node 测试进程中模拟 `window`、`document` 和 DOM；没有它，React Testing Library 无法 `render(<App />)`。

### `desktop/eslint.config.js`

配置了 JavaScript、TypeScript 与 React 的 lint 规则，尤其启用 React Hooks 推荐规则。后续它会帮助发现：

```text
Hook 不在组件顶层调用
useEffect 缺少依赖
不安全的 React refresh 导出
```

### `desktop/.prettierignore`

```text
dist/
src-tauri/gen/
src-tauri/target/
```

这些分别是 Vite 构建产物、Tauri 自动生成 schema、Rust 编译产物。它们不是人工维护的源码，不应格式化或提交。

## 5. Rust/Tauri：`desktop/src-tauri/`

### `Cargo.toml`

这是 Rust 的 package manifest，类似 JavaScript 的 `package.json`。

```toml
[dependencies]
tauri = { version = "2.9.3", features = [] }
tauri-plugin-opener = "2.5.3"

[build-dependencies]
tauri-build = { version = "2.5.0", features = [] }
```

| crate | 职责 |
|---|---|
| `tauri` | 窗口、命令、事件、原生生命周期、打包能力 |
| `tauri-plugin-opener` | 后续使用系统默认程序打开 URL/文件 |
| `tauri-build` | 编译期处理 Tauri 配置、资源和上下文 |

### `Cargo.lock`

由 Cargo 自动生成，锁定完整 Rust 依赖树，确保本地和 CI 的依赖版本一致。不要手动编辑。

### `build.rs`

```rust
fn main() {
    tauri_build::build()
}
```

这是 **构建期** 入口，不是桌面应用运行时入口：

```text
cargo build / cargo test / tauri dev
└── 先运行 build.rs
    └── tauri_build::build()
        └── 读取 tauri.conf.json 并生成所需上下文/资源信息
            └── 再编译应用代码
```

### `src/main.rs`

```rust
fn main() {
    pi_app_desktop_lib::run();
}
```

它是操作系统启动可执行文件时的入口。保持它极小，让 `lib.rs` 承担可测试、可复用的应用装配逻辑。

### `src/lib.rs`

```rust
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_opener::init())
        .run(tauri::generate_context!())
        .expect("error while running Pi App desktop client");
}
```

运行关系：

```text
main.rs::main
└── lib.rs::run
    ├── 创建 Tauri Builder
    ├── 注册 opener 插件
    ├── 编译期加载 generate_context! 中的配置和资源
    └── 创建窗口并进入原生事件循环
```

`expect` 很重要：若桌面应用启动失败，要给出明确错误，不能静默吞掉。

当前 Rust 测试仅验证 crate 能被 Cargo 编译与测试发现。PIA-004 将增加真正的 JSONL RPC、请求 ID、子进程退出等业务测试。

### `tauri.conf.json`

它声明应用标识、窗口和前端如何被加载。

```json
{
  "build": {
    "beforeDevCommand": "npm run dev --workspace @pi-app/desktop",
    "beforeBuildCommand": "npm run build --workspace @pi-app/desktop",
    "devUrl": "http://localhost:5173",
    "frontendDist": "../dist"
  }
}
```

开发模式：

```text
tauri dev
├── 启动 Vite server（localhost:5173）
└── 创建原生窗口，加载 devUrl
```

发布构建：

```text
tauri build
├── 先执行 Vite build
├── 生成 desktop/dist/
└── Tauri 将静态资源打包进原生应用
```

因此最终用户不会运行 Vite server，也不需要浏览器。

### `icons/icon.png`

这是一个最小暂用 PNG。Tauri 的 `generate_context!()` 在构建时需要默认 icon；缺失时 Rust 编译会失败。发布前应替换为正式的多尺寸品牌图标。

## 6. 格式、忽略与 CI

### `.prettierrc.json`

统一前端格式：双引号、尾随逗号。统一格式避免多人协作时因个人编辑器偏好产生无意义 diff。

### `.prettierignore` 与 `.gitignore`

根目录命令与 workspace 命令的工作目录不同，所以分别提供根 `.prettierignore` 和 `desktop/.prettierignore`。

`.gitignore` 中忽略：

```text
desktop/src-tauri/target/  # Cargo 输出
desktop/src-tauri/gen/     # Tauri 生成 schema
```

生成文件可由源码确定性再生，不应提交。

### `.github/workflows/ci.yml`

CI 分成两个独立 job：

```text
CI
├── frontend
│   ├── npm ci
│   ├── format:check
│   ├── lint
│   ├── typecheck
│   ├── extension tests
│   └── frontend tests
└── rust
    ├── stable Rust + rustfmt + clippy
    ├── npm ci
    ├── rust:fmt
    ├── rust:clippy
    └── rust:test
```

拆分后，前端和 Rust 可并行执行，失败时也容易定位。

> 注意：Linux 上完整 Tauri 构建通常还需安装 WebKitGTK 等系统库。当前 CI 建立了验证结构；要在 Ubuntu 上做真正 Tauri 构建时，应补充相应系统包安装步骤。

## 7. 当前与未来的调用关系

当前前端预览：

```text
npm run dev --workspace @pi-app/desktop
└── Vite
    └── http://localhost:5173
        └── React App
```

当前 Rust/Tauri crate 已可编译、lint 和测试，但尚未安装 Tauri CLI 并暴露 `tauri dev` 脚本，因此尚不能一条命令拉起原生窗口。

最终完整链路：

```text
Pi interactive session
└── /app
    └── extensions/app.ts
        └── launcher.startDesktopClient()
            └── pi-app-{platform}-{arch} native binary
                └── Tauri application
                    ├── 创建原生窗口
                    ├── 启动 pi --mode rpc
                    └── 加载 React UI
                        ├── invoke Rust commands
                        └── receive Tauri events
```
